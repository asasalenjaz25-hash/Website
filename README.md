# Repio — Next.js + Tailwind port

A 1:1 port of the Repio HTML theme to **Next.js 16 (App Router) + React 19 + Tailwind CSS 4**.
All 29 pages are real React components on real routes. The visual design is
unchanged — verified by automated pixel and layout comparison against the
original HTML running side by side.

## Run

```bash
npm install
npm run dev     # http://localhost:3000
npm run build && npm start
```

## What was done

**Every page is real JSX.** `scripts/convert.mjs` parses each source HTML file
and emits a proper React element tree — no `dangerouslySetInnerHTML`, no
iframes. HTML attributes are mapped to JSX props (`class`→`className`,
`for`→`htmlFor`, inline `style` strings→style objects), and `.html` links are
rewritten to clean routes (`about.html` → `/about`).

**Tailwind is installed without touching the design.** Tailwind v4 is wired
through `@tailwindcss/postcss` and its utilities are available in every
component. Crucially, `app/globals.css` imports only `theme.css` and
`utilities.css` — **Preflight is deliberately omitted**, because Tailwind's CSS
reset would restyle the theme's base elements and visibly break it. New markup
can use Tailwind utilities freely; existing markup is untouched.

> Note: the theme's own class names (`tw-mt-8`, `tw-rounded-lg`, …) are *not*
> Tailwind — they are hand-written classes in `main.css` that happen to share
> the prefix. They keep working exactly as before.

**Theme CSS is served byte-for-byte.** The seven original stylesheets are
linked from `/public/assets/css` in their original order by `app/layout.jsx`,
so relative `url()` references resolve natively and nothing is rewritten.

**Theme JS keeps working.** `components/ThemeScripts.jsx` loads the 16 vendor
libraries once in their original order, then re-runs the 4 page-init scripts on
each client-side navigation (they bind to page DOM) and tears down
ScrollTrigger/slick instances between routes to prevent leaks.

## Service pages (one per trade)

Each of the theme's 11 home variants is really a different trade (plumbing, AC,
roofing, handyman…). Rather than sending visitors to a *home page*, every trade
is published as its own **service page**:

| Service page | Trade | Same markup as |
| --- | --- | --- |
| `/services/plumbing-service` | Plumbing Service | `/` |
| `/services/laundry-service` | Laundry Service | `/index-2` |
| `/services/repair-service` | Repair Service | `/index-3` |
| `/services/cleaning-service` | Cleaning Service One | `/index-4` |
| `/services/air-conditioning-service` | Air Conditioning Service | `/index-5` |
| `/services/cleaning-service-two` | Cleaning Service Two | `/index-6` |
| `/services/air-conditioning` | Air Conditioning | `/index-7` |
| `/services/handyman` | Handyman | `/index-8` |
| `/services/computer-mobile-repair` | Computer & Mobile Repair | `/index-9` |
| `/services/roofing-services` | Roofing Services | `/index-10` |
| `/services/electrical-service` | Electrical Service | `/index-11` |

The gallery on `/service` links to these service routes — **no card points at a
home route**. Each service page carries its own `<title>`/description for SEO.

The markup lives once in `components/generated/`, imported by both the service
route and its home route, so the two render byte-identical output with no
duplicated JSX. The 11 home routes are **kept**, and all pre-existing
`/service` content (breadcrumb, `service-two-area`) is untouched — the gallery
is appended above the footer, not swapped in.

Both the gallery and the routes are generated by the converter, so they survive
a re-run of `node scripts/convert.mjs`.

## Fix applied during porting

`odometer.min.js` self-initializes only on `DOMContentLoaded`, which has
already fired when scripts are loaded client-side — so the stat counters
rendered blank instead of animating. `ThemeScripts` now calls the library's own
`Odometer.init()` after load. Verified: counters animate and settle to the same
values as the original (`15, 35, 10, 28, 45`).

## Verification

Scripts in `scripts/` compare the port against the original theme served on
`:4321`, using real headless Chrome.

| Script | Purpose |
| --- | --- |
| `convert.mjs` | HTML → JSX generation (re-runnable) |
| `layout2.mjs` | Per-section geometry parity, matched by class |
| `visualdiff.mjs` | Pixel diff at several scroll offsets |
| `noisefloor.mjs` | Diffs a page against itself to measure flakiness |
| `compare.mjs` | Plugin/DOM counts, JS errors, failed requests |
| `gallery.mjs` | Service-page gallery + link checks |
| `servicecheck.mjs` | Service pages match their home counterparts; gallery links |
| `odo.mjs`, `styles.mjs`, `globals2.mjs` | Targeted checks |

Results: **all 29 pages report `ALL MATCHED BLOCKS IDENTICAL (±2px)`** — same
total document height, same offset and height for every section. Zero page
errors, zero broken images, all 20 theme scripts load.

### Reading the numbers honestly

Raw full-page pixel diffs are *not* 0% on a few pages, and that is not a port
defect — those pages are nondeterministic in the **original**. Diffing the
original against *itself* across two loads gives the same 26% on `index-10`,
and its first paint is 195px taller than its settled height (web-font swap).
The port measures 0.00% self-vs-self, i.e. it is strictly more stable. Layout
geometry, which is immune to animation phase, matches exactly on every page.

The only intended difference is `/service`, which is taller by the added
template gallery.

One pre-existing 404 is preserved as-is, not introduced here:
`assets/images/logo/favicon.png` is referenced by the theme but absent from the
original download.
